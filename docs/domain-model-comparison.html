Field-level comparison of the stored MongoDB documents. Hufly side: docs/domain-model.html in HuflyServer. Schneaggchat side: docs/domain-model.html in SchneaggchatV3server, taken from the @Document classes.

RefreshToken

Hufly currently has the minimal session row. Schneaggchat rotates the row in place and keeps the previous hash so a client that lost a refresh response can retry, and it records the device.

FieldHuflySchneaggchatStatus
id, userId, hashedToken, expiresAt, createdAtPresentPresentsame
previousHashedToken, rawToken—Replay recovery after a lost refresh responseSchneaggchat only
deviceName, deviceType—One row per device, login dedupSchneaggchat only

Event and participation

Schneaggchat embeds invitations and answers in the event document. Hufly keeps one EventInvitation document per invited user, so an invitee's answer is a small write that syncs on its own.

Only on one side

Schneaggchat only, not needed in Hufly

  • Friends: Friendship, FriendshipSetting
  • Chat: Group, GroupMember, Message
  • Map: MapEntry, MapEntryVersion, UserLocation
  • Push tokens and presence: ApnsToken, FirebaseToken, ConnectionLogEntry (Hufly needs token collections once push notifications land)
  • Games: GameScore
  • Website: Donation, FaqEntry
  • Infrastructure: VersionCounter, Log

Hufly only

  • Stable with SubscriptionStatus
  • Tag with TagType and Permission
  • Horse with embedded Vaccination and Medication
  • FoodPlanEntry with MealSlot
  • EventInvitation as its own collection
  • StableTask
  • UserSettings as its own collection

Worth reusing from Schneaggchat

Paths relative to src/main/kotlin/com/lerchenflo/schneaggchatv3server/.

  • Refresh token replay recovery and device dedup: authentication/AuthService.kt, authentication/model/RefreshToken.kt
  • Soft-delete synced feature with controller, service and sync endpoint: schneaggmap/SchneaggmapController.kt, schneaggmap/SchneaggmapService.kt
  • Version-based delta sync if timestamps prove unreliable: util/VersionCounterService.kt, util/SyncCollection.kt
  • Retry on concurrent writes: util/OptimisticRetry.kt
  • Canonical auth helper: core/security/RequireAuth.kt
  • Expired data cleanup (TTL indexes do not work on kotlin.time.Instant there): core/DatabaseCleanupTask.kt
  • Login rate limiting: core/security/ratelimit/RateLimitFilter.kt
  • Profile and horse pictures: util/ImageManager.kt
  • Push fan-out (WebSocket, FCM, APNs) for event invitations later: notifications/NotificationService.kt
  • Error responses and input checks: core/GlobalExceptionHandler.kt, util/ValidationUtils.kt
